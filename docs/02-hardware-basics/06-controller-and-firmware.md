# 6. 主控、控制板与固件

## 6.1 主控与控制板 {#controller-roles}

机器人里通常有两台承担不同工作的计算设备。主控运行 Ubuntu、ROS 2、导航和视觉程序；底盘控制板靠近电机，按固定周期读取反馈并输出控制信号。主控擅长运行较大的程序，控制板擅长稳定地处理实时输入和输出。判断故障时，主控能登录不等于控制板已经正常，控制板亮灯也不等于 ROS 2 已经连接。

电机驱动器位于控制板和电机之间。控制板输出的是方向、使能或 PWM 等信号，驱动器才负责承受电机电流。把控制板信号线直接接到电机端子会损坏设备。

## 6.2 CPU、MCU 与 STM32 {#cpu-mcu-stm32}

中央处理器（Central Processing Unit, CPU）执行通用程序指令，通常拥有较大的内存和复杂的操作系统。图形处理器（Graphics Processing Unit, GPU）擅长并行处理图形和机器学习计算，部分主控会把视觉模型交给 GPU 运行。微控制器（Microcontroller Unit, MCU）把处理器、存储器和输入输出外设集成在一块芯片上，适合在确定的时间间隔读取传感器和控制执行器。STM32 微控制器（STM32 Microcontroller）是 STMicroelectronics 生产的 32 位 MCU 产品系列，常见于 WHEELTEC 底盘控制板。

CPU 上的程序可以同时处理网络、图像和文件；MCU 上的程序通常围绕定时器、中断、串口、编码器和电机控制循环运行。两者通过串口、CAN 或其他接口交换命令和状态。

## 6.3 源码、固件与构建结果 {#source-firmware-build}

源码是人可以阅读和修改的程序文件。固件（Firmware）是写入控制板非易失存储器、上电后直接运行的程序。构建使用编译器和链接器把源码转换成目标文件，常见输出是 `.hex` 或 `.bin`。构建成功只说明工具链生成了文件，还没有说明文件适合当前控制板。

选择固件至少要同时核对控制板型号、MCU 型号、底盘运动形式、编码器类型、引脚分配和协议版本。文件名、购买年份或外壳颜色都不能单独作为匹配依据。

## 6.4 烧录与回滚 {#flash-rollback}

烧录把构建结果写入 MCU 的存储器。开始前保存当前固件、参数、控制板丝印和接线照片，并准备一条断电和恢复路径。首次运行保持电机失能或轮子架空，先观察自检、状态显示、通信和编码器反馈，再进行低速动作。

回滚是写回已验证的旧固件和参数。控制板常把车型、纠偏值等配置保存在电可擦可编程只读存储器（Electrically Erasable Programmable Read-Only Memory, EEPROM）或其他非易失存储区，烧录程序未必会覆盖这些参数。回滚后仍要复测车型、轮号、编码器方向、急停和通信超时；旧固件恢复成功不代表接线或机械状态没有变化。

## 6.5 电源域、信号域与功率级

电池和变压模块提供电源；USB、UART、CAN、GPIO 等接口传递信号；电机驱动器和电机组成功率级。电源电压、电流能力、信号电平和接地方式分别决定设备能否安全连接。出现异常发热、复位或自主运动时，先断电并回到电源和控制板层检查。

## 6.6 观察练习

在一张机器人照片或实物上标出主控、控制板、电机驱动器和电机。为每条连接写出它传递的是电能、控制信号还是反馈数据，并说明该连接断开时会看到什么现象。

## 6.7 本章小结

主控运行较大的机器人程序，控制板运行靠近硬件的实时程序，电机驱动器处理功率。源码经过构建才形成固件，烧录和回滚分别改变控制板中的运行程序。后面的接口、传感器和运动控制都建立在这条分工上。
