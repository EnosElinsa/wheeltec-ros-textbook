# 6. 主控、控制板与固件

## 6.1 主控与控制板 {#controller-roles}

在一台轮式机器人中，主控、控制板、电机驱动器和电机处在同一条执行链上，各自承担不同工作。主控运行 Ubuntu、ROS 2 以及导航、视觉和任务程序；控制板处理靠近电机的输入输出；电机驱动器根据控制信号调节电流；电机与机械结构完成运动。主控和控制板之间交换运动目标、反馈和设备状态，这个分工决定了程序、接口和测试点分别位于哪一层。

## 6.2 CPU、MCU 与 STM32 {#cpu-mcu-stm32}

主控与控制板的差别，首先体现在处理任务和时间尺度上。中央处理器（Central Processing Unit, CPU）运行操作系统和应用程序；图形处理器（Graphics Processing Unit, GPU）承担视觉模型等并行计算；控制板常用的微控制器（Microcontroller Unit, MCU）把处理器、存储器和输入输出外设集成在一块芯片中，按固定周期处理底层信号。STM32 是常见的 MCU 产品系列，在 WHEELTEC 底盘控制板中经常出现。

CPU 上的程序可以同时处理网络、图像和文件；MCU 上的程序围绕定时器、中断、串口、编码器和电机控制循环运行。两者通过串口、控制器总线或其他接口交换命令和状态。

## 6.3 源码、固件与构建结果 {#source-firmware-build}

修改底盘程序时，通常会同时接触源码、构建结果和控制板中的固件（Firmware）。源码经过编译和链接生成 `.hex` 或 `.bin` 等文件，烧录器把适配当前控制板的构建结果写入存储器。接下来核对设备型号、MCU、车型、编码器、引脚和协议。

核对时以控制板丝印、硬件连接、配置文件和协议记录为准。

## 6.4 烧录与回滚 {#flash-rollback}

烧录把构建结果写入 MCU 的存储器。开始前保存当前固件、参数、控制板丝印和接线照片，并准备断电和恢复路径。首次运行保持电机失能或轮子架空，依次观察自检、状态显示、通信和编码器反馈，再进行低速动作。

回滚通常包含程序、参数和验证记录。控制板可能把车型、纠偏值等配置保存在电可擦可编程只读存储器（Electrically Erasable Programmable Read-Only Memory, EEPROM）或其他非易失存储区，程序存储区与配置存储区可以分开。回滚后按启动清单重新检查车型、轮号、编码器方向、急停和通信超时，并记录复测结果。

## 6.5 电源域、信号域与功率级

电池和变压模块提供电源；计算机接口、串行接口、控制器总线和数字引脚传递信号；电机驱动器和电机组成功率级。电源电压、电流能力、信号电平和接地方式共同决定连接条件。出现异常发热、复位或自主运动时，先断电，再从电源和控制板层开始检查。

## 6.6 观察练习

在一张机器人照片或实物上标出主控、控制板、电机驱动器和电机。为每条连接注明传递的是电能、控制信号还是反馈数据，再写出对应的观察点：程序、接口、指示灯或运动结果。

## 6.7 本章小结

主控负责上层计算，控制板负责底层输入输出，电机驱动器处理功率，电机和机械结构完成执行。源码经构建形成固件，烧录与回滚改变控制板中的运行程序；接口、传感器和运动控制都建立在这条设备分工上。
