# 8. 传感器与状态反馈

## 8.1 环境信息与机器人自身状态

传感器把物理世界或机器人自身状态转换成程序可读的数据。环境传感器观察墙体、障碍物和图像；本体传感器观察轮子转动、加速度、角速度、电压或开关状态。数据进入 ROS 2 前还要经过驱动节点、话题、时间戳和坐标系转换。

## 8.2 编码器怎样记录转动 {#encoder}

编码器（Encoder）把电机轴或车轮的转动转换为脉冲、角度或位置数据。控制板按采样时间统计脉冲增量，得到轮速；再结合轮半径和减速比，估计机器人移动了多远。编码器方向、每转计数和轮号必须与实际安装一致。

## 8.3 GMR 与霍尔效应编码器 {#encoder-types}

巨磁阻（Giant Magnetoresistance, GMR）编码器利用磁阻随磁场变化的特性检测转动。霍尔效应编码器（Hall Effect Encoder）利用霍尔元件检测磁场变化并输出转动脉冲。两者都能形成 A/B 相反馈，但供电、接线、脉冲特性和配套固件可能不同，不能只按插头外观选择固件。

## 8.4 IMU 怎样测量运动 {#imu}

惯性测量单元（Inertial Measurement Unit, IMU）通常包含加速度计和陀螺仪，分别测量线性加速度和角速度。静止时可以观察零偏和噪声，转动时可以检查轴方向和符号。对角速度或加速度做积分会积累偏差，所以 IMU 适合与轮速或其他观测融合，不直接等同于绝对位置。

## 8.5 OLED 是状态窗口 {#oled}

有机发光二极管（Organic Light-Emitting Diode, OLED）显示屏是底盘控制板的本地状态窗口。它可能显示车型、自检、使能、供电、电机目标和编码器反馈。屏幕显示异常时先保存照片，结合控制板型号和接线判断；显示正常只说明控制板有一组可观察状态，不代表主控通信已经通过。

## 8.6 激光雷达、相机与 GNSS {#lidar-camera-gnss}

激光雷达（Light Detection And Ranging, LiDAR）按方向测量周围物体的距离，常发布二维扫描或点云。相机输出图像，后续视觉节点再从图像中提取目标、线或标签。全局导航卫星系统（Global Navigation Satellite System, GNSS）通过卫星信号估计位置和时间，在室内或遮挡环境中可能不可用。

不同传感器的测量频率、安装位置和坐标方向各不相同。设备被 Linux 识别后，还要确认驱动节点运行、话题持续发布、时间戳有效，并且 `frame_id` 与实际安装方向一致。

## 8.7 采样、时间与坐标方向

采样频率决定数据更新有多快，时间戳说明数据测量发生在什么时候。机器人运动时，雷达、IMU、编码器和相机的数据必须在可比较的时间范围内对齐。坐标方向决定“正前进”和“正转动”的符号；安装方向或驱动转换错误会让数据看起来有值，却无法用于建图和控制。

## 8.8 本章小结与观察练习

编码器描述轮子怎样转，IMU 描述机器人怎样加速和旋转，OLED 提供控制板本地状态，激光雷达、相机和 GNSS 描述环境或全局位置。任何传感器结论都要同时考虑设备、驱动、频率、时间和坐标。

选择一台机器人，分别记录一个编码器、IMU 和环境传感器的安装位置、输出数据、频率和坐标系。写出其中一项数据异常时应先检查哪一层。
