# 8. 传感器与状态反馈

第 7 章说明了数据怎样从设备进入通信链路。本章转向数据本身：编码器记录车轮运动，惯性测量单元记录车体的加速度和旋转，控制板显示屏提供本地状态，激光雷达、相机和卫星定位系统描述环境或全局位置。最后把采样时间和坐标方向放回同一套判断中。

## 8.1 环境信息与机器人自身状态

传感器输出的内容可以分为两类：环境观测描述墙体、障碍物和图像，本体状态描述轮子转动、加速度、角速度、电压或开关状态。数据进入 ROS 2 前，还要经过驱动节点、话题、时间戳和坐标系转换。

## 8.2 编码器怎样记录转动 {#encoder}

编码器（Encoder）把电机轴或车轮的转动转换为脉冲、角度或位置数据。控制板按采样周期统计脉冲增量，得到轮速，再结合轮半径和减速比估计车体移动距离。编码器方向、每转计数和轮号需要与实际安装和配置对应。

## 8.3 GMR 与霍尔效应编码器 {#encoder-types}

底盘常见的磁式编码器包括巨磁阻（Giant Magnetoresistance, GMR）编码器和霍尔效应编码器（Hall Effect Encoder）。GMR 器件利用磁阻随磁场变化的特性检测转动，霍尔器件利用霍尔元件检测磁场变化；两者都可以形成 A/B 相反馈。更换或匹配器件时，按供电、接线、脉冲特性和配套固件逐项确认，插头外观无法提供这些参数。

## 8.4 IMU 怎样测量运动 {#imu}

惯性测量单元（Inertial Measurement Unit, IMU）通常包含加速度计和陀螺仪，分别测量线性加速度和角速度。静止时可以观察零偏和噪声，转动时可以检查轴方向和符号。角速度或加速度积分会积累偏差，因此 IMU 主要描述短时间内的运动变化，绝对位置需要结合轮速、地图或其他观测。

## 8.5 OLED 是状态窗口 {#oled}

有机发光二极管（Organic Light-Emitting Diode, OLED）显示屏提供控制板的本地状态。它可能显示车型、自检、使能、供电、电机目标和编码器反馈。排查时保存屏幕照片，再与控制板型号和接线记录对照；主控通信仍需从接口和 ROS 2 数据中确认。

## 8.6 激光雷达、相机与 GNSS {#lidar-camera-gnss}

激光雷达（Light Detection And Ranging, LiDAR）按方向测量周围物体的距离，常发布二维扫描或点云。相机输出图像，视觉节点再从图像中提取目标、线或标签。全局导航卫星系统（Global Navigation Satellite System, GNSS）通过卫星信号估计位置和时间，室内或遮挡环境会削弱这类观测。

不同传感器的测量频率、安装位置和坐标方向各不相同。设备被 Linux 识别后，还要确认驱动节点运行、话题持续发布、时间戳有效，并让 `frame_id` 与实际安装方向对应。

## 8.7 采样、时间与坐标方向

采样频率决定数据更新速度，时间戳记录测量发生的时刻。机器人运动时，雷达、IMU、编码器和相机的数据需要在可比较的时间范围内对齐。坐标方向约定“正前进”和“正转动”的符号；安装方向和驱动转换应与 `frame_id` 保持一致，建图和控制才能正确使用这些数据。

## 8.8 本章小结与观察练习

编码器提供轮子转动信息，IMU 提供车体运动变化，OLED 展示控制板状态，激光雷达、相机和 GNSS 提供环境或全局位置观测。判断一项数据能否使用时，要把设备、驱动、频率、时间和坐标放在一起看。

选择一台机器人，记录一个编码器、IMU 和环境传感器的安装位置、输出数据、频率和坐标系。为每项数据注明对应的设备、驱动节点和话题，并写出一条可观察的检查路径。
