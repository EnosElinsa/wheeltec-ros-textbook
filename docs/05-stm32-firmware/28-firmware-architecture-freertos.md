# 28. 固件架构与 FreeRTOS 任务

## 本章目标

从程序入口追踪初始化、中断和 FreeRTOS 任务，知道速度命令在哪接收、电机在哪更新、状态在哪发送，自检失败又在哪阻止电机使能。

## 适用范围

WHEELTEC STM32 底盘固件。不同控制板的外设和任务名会变化，本文讲职责，不假定函数名完全一致。

## 开始前检查

- 只读当前匹配控制板的源码，不先改代码。
- 保存工程、编译器版本和宏定义。
- 能从源码恢复到出厂固件。

## 工作原理

典型固件由启动初始化、周期任务和中断组成。串口/CAN 接收常由中断或 DMA 提供数据，控制任务按周期更新运动学与 PI，传感器任务读取 IMU/编码器，通信任务发送状态，人机任务刷新 OLED、蜂鸣器和按键。

实时性来自明确周期和优先级，不是“任务越多越好”。控制周期抖动会直接影响编码器测速、PI 参数和里程计积分。

## 操作步骤

1. 从 `main()` 画出时钟、GPIO、串口、CAN、定时器、编码器和 IMU 初始化顺序。
2. 找到调度器启动位置，列出任务名、周期/延时、优先级和共享数据。
3. 从串口/CAN 接收函数追踪到机器人目标速度。
4. 从控制任务追踪逆运动学、PI、PWM 和电机方向。
5. 从编码器/IMU 追踪正运动学、状态帧和 OLED。
6. 找到自检和失能条件，记录哪些异常会阻止输出。
7. 标记中断与任务共同访问的变量，检查临界区和数据一致性。

## 结果验收

- 有一张命令到执行、反馈到上报的任务图。
- 控制周期和测速周期明确。
- 自检、急停、通信超时和电机失能路径可定位。
- 共享变量的生产者、消费者和更新时机明确。

## 常见故障与处理

| 现象 | 检查 |
|---|---|
| 偶发速度跳变 | 接收帧一致性、共享变量和任务周期 |
| OLED 卡住但电机仍动 | 人机任务阻塞或优先级问题 |
| 通信正常但控制更新慢 | 控制任务延时、阻塞调用或优先级 |
| 自检偶发失败 | 初始化顺序、传感器稳定时间和电压 |
