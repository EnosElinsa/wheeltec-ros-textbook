# 41. 语音、多模态 AI 与 OpenClaw

## 41.1 学习目标

把语音、视觉或聊天入口接到机器人上层决策，同时保留确定性的指令校验、速度限制和停止链。

## 41.2 适用范围

ROS 2 TTS、多模态大模型交互和 OpenClaw 应用。外部 API、QQBot 等网络服务只作为可选入口。

## 41.3 操作前检查

- 核心底盘、传感器和导航不依赖大模型也能独立验收。
- API 凭据不写入源码、日志或教材。
- 运动命令采用白名单，急停不经过云服务。

## 41.4 工作原理

AI 适合把自然语言转换成高层意图，例如“去实验室门口”。它不适合直接连续生成轮速。安全架构应把输出限制为经过验证的动作/目标，再由 ROS 状态机、Nav2 或固定控制器执行。

## 41.5 操作步骤

1. 单独验证麦克风、语音识别和 TTS，不连接运动。
2. 记录模型输入、结构化输出和解析失败行为。
3. 为可执行意图建立白名单、参数范围和确认步骤。
4. 把导航类指令转换为 Nav2 目标，把简单动作转换为短时受限命令。
5. 超时、网络断开、模型拒答或格式错误时保持停止。
6. OpenClaw/聊天机器人只调用上述受控接口，不直接访问串口或 PWM。
7. 日志隐藏令牌和个人消息，记录决策来源与最终动作。

## 41.6 验收标准

- 无网络或无模型时，底盘基础功能仍正常。
- 非白名单、歧义和越界命令不会执行。
- 每次运动有明确超时、最大速度和停止条件。
- 急停和底盘通信超时不依赖 AI 服务。

## 41.7 故障排查

| 现象 | 处理 |
|---|---|
| 同一句话动作不一致 | 使用结构化输出、低随机性和规则校验 |
| 模型返回文本无法解析 | 拒绝执行并记录原始响应 |
| 网络中断后动作持续 | 上层心跳和底盘超时必须独立生效 |
| 令牌出现在日志 | 立即撤销，改用环境变量或安全凭据存储 |
