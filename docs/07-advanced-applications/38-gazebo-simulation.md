# 38. 仿真与 Gazebo

## 本章目标

用仿真验证 ROS 接口、Launch、TF、导航参数和算法流程，同时明确哪些结论必须回到实机重测。

## 适用范围

WHEELTEC 已提供 Gazebo 模型或功能包的机器人。资料中的部分教程基于 ROS 1，ROS 2 使用时只借鉴模型与诊断思路，不照搬命令。

## 开始前检查

- 仿真包与 ROS/Gazebo 版本匹配。
- 不与实机底盘节点共用同一命名空间和速度话题。
- 记录模型轮径、质量、惯量、摩擦和传感器参数。

## 工作原理

Gazebo 用物理模型近似底盘和传感器。它适合检查节点连接和算法状态机，但不能真实复现 USB 掉线、电池压降、编码器噪声、轮胎形变和现场光照。

## 操作步骤

1. 只启动世界和机器人模型，检查模型是否掉落、抖动或穿透地面。
2. 检查 TF、关节状态和仿真时间。
3. 发布小速度，确认轮子、里程计和坐标方向。
4. 加载雷达与相机插件，检查话题类型和频率。
5. 再接入 SLAM/Nav2，保存参数和结果。
6. 为实机列出必须重测的项目：制动距离、转向极限、传感器盲区、速度上限和故障停止。

## 结果验收

- 模型与真实底盘自由度一致。
- 话题、TF 和命名空间不会与实机冲突。
- 仿真速度与里程计方向正确。
- 算法流程可运行，实机待验证项有清单。

## 常见故障与处理

| 现象 | 检查 |
|---|---|
| 模型弹飞 | 惯量、碰撞体和初始姿态 |
| 轮子转但车不走 | 摩擦、关节轴、插件和控制接口 |
| 时间戳异常 | `/use_sim_time` 和 `/clock` |
| 仿真能导航、实机不能 | 回到传感器、TF、里程计和制动能力 |
