# 45. 日志、备份、升级与恢复

## 本章目标

在升级前留下可恢复基线，升级后能判断改变了什么。备份不是把整个硬盘随手复制一份，而是让配置、源码、固件、地图和系统镜像各自有明确恢复位置。

## 适用范围

所有 WHEELTEC 主控和底盘控制板。系统镜像工具按树莓派、Jetson、RDK、Atlas 和 IPC 平台选择。

## 开始前检查

- 第 44 章的部署基线和本章需要备份的对象已经列出；最终验收由下一章统一执行。
- 备份介质容量、校验方式和存放位置明确。
- 升级窗口内有人能执行急停、断电和本地恢复。

## 工作原理

恢复分四层：配置文件、ROS/STM32 源码与固件、地图/数据、系统镜像。低层恢复会覆盖高层内容，因此顺序应从系统可启动性、环境、源码/固件、配置、地图到功能验收逐层确认。

## 操作步骤

### 升级前

保存：

```text
baseline/
├── hardware.md
├── os-and-ros.txt
├── workspace-file-list.txt
├── configuration/
├── firmware/
├── maps/
├── logs/
└── checksums.sha256
```

记录 `ros2 pkg prefix`、关键参数、设备列表、TF、话题频率和启动日志。固件还要记录控制板、车型、编码器、TYPE、纠偏值和舵机零位。

### 升级后

1. 先确认系统能启动、网络可用。
2. 再确认 ROS 环境和工作空间。
3. 只启动底盘，完成低速停止测试。
4. 逐个恢复传感器、TF、地图和导航。
5. 对比升级前后日志和参数，不要一次启动所有应用。

### 恢复

先恢复最近一次可启动系统，再恢复源码/固件和配置，最后恢复地图与应用。每层恢复后都执行对应验收，不跨层猜测。

## 结果验收

- 备份文件可读，哈希记录完整。
- 至少演练一次从备份恢复配置或固件。
- 升级前后平台、ROS、源码和参数差异有记录。
- 失败时能回到已验证的底盘停止状态。

## 常见故障与处理

| 现象 | 处理 |
|---|---|
| 备份存在但无法恢复 | 校验文件、版本、工具和介质 |
| 升级后 ROS 启动但底盘不动 | 分层检查串口、固件、参数和使能 |
| 地图加载失败 | 路径、权限、分辨率和版本 |
| 自启动进入重启循环 | 禁用服务，回到手动基线 |
