# T1. ROS 2 是什么

## 本章目标

把 ROS 2 放回 WHEELTEC 机器人的实际结构中。读完后，你应能区分 Ubuntu、ROS 2、节点和 STM32 固件的职责，也能说清楚为什么 ROS 2 不是一块“控制板”。

## 适用范围

| 项目 | 说明 |
|---|---|
| 主线 | ROS 2 Humble 等 WHEELTEC 镜像，具体发行版以实机为准 |
| 主控 | Jetson、树莓派、RDK、Atlas 或工控机 |
| 底层 | WHEELTEC STM32 控制板、电机驱动器、编码器和 IMU |
| 读者 | 已拿到机器人，需要理解并维护现有系统的工程使用者 |

## 开始前检查

- 已读完第 1 章，知道自己的主控、底盘和控制板。
- 能通过本地显示器或 SSH 打开主控终端。
- 不需要为了读理论章节启动电机或修改任何配置。

## 工作原理

ROS 2 运行在 Ubuntu 等操作系统之上。它提供通信、工具、接口和运行管理方式，让多个机器人程序能够交换数据；它本身不负责给电机提供大功率，也不替代 STM32 的实时控制。

在 WHEELTEC 机器人中，可以先按下面的职责理解：

```text
Ubuntu 主控
  └─ ROS 2 节点：底盘、雷达、相机、定位、导航、视觉
       └─ 串口/CAN 消息
            └─ STM32 底盘控制板
                 ├─ 电机驱动器 → 电机
                 ├─ 编码器 → 速度/里程计反馈
                 └─ IMU → 姿态相关反馈
```

Ubuntu 管理进程、文件和设备；ROS 2 节点执行机器人功能；DDS 负责节点发现和通信传输；STM32 以确定的周期完成底层采样、闭环和失能保护。上层命令能到达节点，不等于电机一定运动；底层还要检查控制板自检、使能、协议和硬件。

ROS 2 的“操作系统”名称容易造成误解。它更像一套机器人软件框架和通信约定：节点可以用 C++ 或 Python 编写，功能包负责组织代码和资源，Launch 负责组合启动，工具负责观察运行状态。

## 操作步骤

### 1. 查看 ROS 2 是否在当前终端可用

在主控终端执行：

```bash
printenv ROS_VERSION
printenv ROS_DISTRO
which ros2
```

`ROS_VERSION=2` 和可找到 `ros2` 命令，说明当前终端已经加载了 ROS 2 的一部分环境。变量为空时不要立即判断系统没有 ROS 2，先看第 3 章的环境加载方法。

### 2. 把一个功能拆成四层

以“雷达参与导航”为例：

1. Ubuntu 识别 USB 或网络设备。
2. 雷达驱动节点读取设备并发布扫描/点云话题。
3. 定位或代价地图节点订阅数据并计算状态。
4. Nav2 控制器产生速度，底盘节点通过串口/CAN 交给 STM32。

任何一层没有运行，最终都可能表现成“导航不能走”。调试时沿层次向下查，而不是先重装全部软件。

### 3. 观察一个真实运行图

如果机器人当前已启动底盘，执行：

```bash
ros2 node list
ros2 topic list -t
```

记下底盘节点、速度话题和里程计话题。若没有节点，先不要继续解释话题；当前系统还没有建立可观察的 ROS 2 图。

## 结果验收

- 能用自己的机器人举出一个 ROS 2 节点和一个 STM32 职责。
- 能说明 `ros2` 命令依赖 Ubuntu 和已加载的环境。
- 能画出一条从速度命令到电机、再从编码器回到 ROS 2 的链路。
- 能解释“ROS 节点启动成功”和“底盘可以安全运动”是两个验收结论。

## 常见故障与处理

| 误解/现象 | 正确判断 |
|---|---|
| ROS 2 命令存在但轮子不动 | 继续查底盘节点、串口/CAN、使能、自检和 STM32 |
| STM32 能控制电机但没有 ROS | STM32 是底层执行，不需要 ROS 才能做独立遥控测试 |
| 终端找不到 `ros2` | 检查发行版安装和 `setup.bash`，不要先改源码 |
| 只看 RViz 判断系统正常 | RViz 是显示工具，必须同时看节点、话题、频率和 TF |
