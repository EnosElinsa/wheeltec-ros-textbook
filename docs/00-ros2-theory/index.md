# 卷零：ROS 2 理论基础

这一卷回答一个实际问题：机器人启动后，主控、底盘、传感器和导航节点为什么能够互相找到并交换数据？先建立这张系统图，再读后面的操作章节，遇到报错时就能判断该查哪一层。

理论章节不要求你先写完整 ROS 程序。每一章都用 WHEELTEC 的底盘、雷达、相机或导航链路作例子，最后给出一个可以在主控上观察的检查。

## 四章内容

1. [T1：ROS 2 是什么](t1-what-is-ros2.md)：ROS 2、Ubuntu、节点、DDS 和 WHEELTEC 主控/底盘的关系。
2. [T2：ROS 2 系统图与通信模型](t2-graph-and-communication.md)：节点、话题、服务、动作、参数和接口怎样组成一张运行图。
3. [T3：工作空间、功能包与运行时环境](t3-workspace-package-runtime.md)：源码、构建结果、环境叠加、Launch、命名空间和 Docker 边界。
4. [T4：时间、QoS、TF 与实机诊断](t4-time-qos-tf-diagnosis.md)：为什么“节点存在”仍可能收不到数据，以及怎样用时间和坐标证据定位问题。

## 读完后的最低能力

- 能画出 `ROS 2 主控 → 底盘节点 → 串口/CAN → STM32 → 电机` 的控制链。
- 能从节点图找到速度、里程计、IMU、雷达和相机的生产者与消费者。
- 能解释一次 `ros2 topic echo` 没有数据可能对应的多个原因。
- 能区分源码、安装结果、参数文件和运行时环境。
- 能看懂 `map → odom → base_link → sensor` 这条 TF 链。
