# 43. R680 底盘调试、源码与固件维护 {#r680-code-resource}

!!! example "本章代码：C50C F407 麦轮霍尔编码器固件"
    使用 [r680/firmware/c50c/f407-mecanum-hall-single-serial-can-b01](https://github.com/EnosElinsa/wheeltec-ros-source-reference/tree/0ecdda9102755150f466d4de96e418ed4460575a/r680/firmware/c50c/f407-mecanum-hall-single-serial-can-b01) 的 `USER/WHEELTEC.uvprojx`、`USER/main.c`、`HARDWARE/usartx.c` 和 `HARDWARE/can.c`，用于静态诊断串口与 CAN 控制链。

    验收：能定位工程、主循环和双协议接口。边界：没有匹配实机照片、接线和测量证据时，只能静态阅读；不得据此烧录或声明硬件验证。

    其他控制板、底盘和编码器组合当前不可用且没有公开可消费固件资源；在具备独立矩阵、完整工程和照片支持前，不应从本变体外推。

## 43.1 学习目标

按控制板、底盘和编码器选择 R680 源码或固件，完成架空测试、低速验收和回滚；同时处理 8 驱主从、霍尔编码器和阿克曼零位等分支。

## 43.2 适用范围

当前主线为 C50C。C50A/C50B 只使用对应的旧版工程；下表用于选择分支，不代表未核对实机就可以烧录。

| 控制板 | 底盘/编码器 | 应选分支 | 日期/状态 | 使用条件 |
|---|---|---|---|---|
| C50C | 通用车型，标准编码器 | 当前 C50C 通用工程 | 2026-08-25 基线 | 核对工程内车型与硬件版本 |
| C50C | 阿克曼 | C50C 阿克曼分支 | 2026-05-29 基线 | 先保存舵机零位和原固件 |
| C50C | 差速 | C50C 差速分支 | 2026-05-29 基线 | 核对电机数量与轮号 |
| C50C | 麦轮 | C50C 麦轮分支 | 2026-05-29 基线 | 核对滚子方向与 A/B/C/D |
| C50C | 全向轮 | C50C 全向轮分支 | 2026-05-29 基线 | 核对轮组结构 |
| C50C | 四驱 | C50C 四驱分支 | 2026-05-29 基线 | 不按麦轮横移测试 |
| C50C | 8 驱麦轮 | 8 驱主从专项分支 | 旧版专项 | 必须确认主从控制板和通信 |
| C50C | 霍尔编码器 | 霍尔编码器分支 | 特殊版本 | 核对电机外观和排线 |
| C50A/C50B | 各车型 | 对应控制板的旧版工程 | 仅维护 | 不套用 C50C 固件 |

## 43.3 操作前检查

!!! danger "烧录前先备份并限制运动"
    保存可运行固件、TYPE、纠偏值和阿克曼舵机零位。第一次启动必须关闭使能或架空轮子，并准备急停。

1. 第 42 章硬件记录已完成。
2. 原接线、OLED 和遥控基线有照片/视频。
3. 下载工具、控制板供电和恢复固件已验证。
4. 源码/固件的控制板、底盘、编码器三项完全匹配。

## 43.4 工作原理

R680 的车型分支会改变运动学、轮号、舵机、编码器和自检。8 驱结构还可能使用主控制板向从控制板分发轮速；只烧录一侧或主从版本不一致，会造成部分轮组无响应。

测试固件用于把 ROS 与底盘硬件隔离，但它同样会驱动电机。测试固件通过不代表正式固件配置正确，正式固件失败也不等于电机一定损坏。

## 43.5 操作步骤

### 1. 先验证现有底盘

按第 5、7、37 章保存遥控、OLED、目标/实际值和接线基线。问题只出现在 ROS 时，不应先烧 STM32。

### 2. 选择源码而不是猜固件

优先使用与实机控制板匹配的源码工程，阅读工程指南和车型选择。无源码时才使用已确认匹配的 `.hex`。对同名归档比较 SHA-256，避免重复副本造成“版本很多”的错觉。

### 3. 执行架空测试

烧录后保持电机失能，先看 OLED、TYPE、IMU 和通信。随后架空轮子：

1. 分别给小的前进、后退、转向/横移命令。
2. 记录每个轮子的目标和实际值。
3. 失能、急停和断开通信，确认 PWM 归零。
4. 霍尔版重点看排线和计数方向。
5. 阿克曼重点看舵机回正、机械限位和滑轨反馈。

### 4. 处理 8 驱主从结构

确认主/从板标识和各自源码。先单独验证通信和轮号，再让八个电机架空运行。主板目标、从板接收和从属轮编码器应同时记录。不能用普通四轮固件替代主从逻辑。

### 5. 落地低速验收

通过架空测试后，在平整场地低速完成直行、停止和转向。持续偏移按第 17 章分类，先排除机械和编码器，再考虑纠偏。

### 6. 失败回滚

出现 TYPE 异常、轮号混乱、舵机顶死或通信丢失时立即断电：

1. 烧回保存的出厂固件；
2. 恢复 TYPE、纠偏和舵机零位；
3. 恢复原接线；
4. 重做第 42 章基线；
5. 比较烧录前后的证据，定位是固件还是硬件变化。

## 43.6 验收标准

- 兼容表中的控制板、底盘、编码器与实机一致。
- 架空测试中轮号、方向、编码器和停止逻辑正确。
- 阿克曼舵机不顶限位，闭环反馈连续。
- 8 驱主从的目标、通信和八轮反馈完整。
- 落地低速测试可控，无异常发热和持续打滑。
- 回滚后能恢复烧录前基线。

## 43.7 故障排查

| 现象 | 优先检查 |
|---|---|
| 烧录后 `TYPE X` | 工程车型、编码器版本、线束和电压 |
| 只有部分轮子转 | 轮号、驱动器、主从通信和从板固件 |
| 霍尔版速度异常 | 特殊源码、排线线序、计数倍率 |
| 阿克曼无法回正 | 舵机零位、TYPE、连杆和反馈电位器 |
| 测试固件正常、正式固件异常 | 正式工程配置、协议和任务逻辑 |
| 回滚仍无法恢复 | EEPROM 参数、接线或机械状态也改变 |
