# 54. 多机编队与 Qt 控制界面

从一台机器人扩展到多台时，首先遇到的是身份和指令归属问题：同名话题可能让命令发给错误的车，重复启动驱动可能造成控制冲突。统一的控制界面也需要准确区分每台机器人的状态与任务。

本章把多机编队与 Qt Application Framework（Qt）界面放到同一套 ROS 2 接口中理解。先用机器人标识、命名空间和 Domain ID 组织通信，再让 Qt 客户端显示反馈并发送受限目标，最后通过逐台接入检查状态归属与速度发布者。底盘执行与停止逻辑继续由各车的控制链处理。

## 54.1 学习目标

让多台机器人和 Qt 客户端接入既有 ROS 2 系统，逐台核对节点与话题归属，确认没有命名冲突、话题串车和重复速度发布。

## 54.2 适用范围

ROS 2 多机器人编队与 Qt 控制界面。不同车型的编队接口和控制包需要分别核对。

## 54.3 操作前检查

- 单车底盘和网络分别通过。
- 每台机器有唯一名称、IP、命名空间和配置记录。
- 急停和单车停止命令不依赖编队节点。

## 54.4 工作原理 {#qt-client}

多机系统可以共享网络，但每台机器的状态和命令要有明确归属。逻辑标识符（Logical Identifier, ID）用于在配置和界面中区分机器人；命名空间给节点和话题加前缀；Domain ID可以把不同 ROS 2 通信域分开。Qt 客户端只订阅反馈并发布经过限制的目标，不再启动一套底盘驱动，也不把界面按钮状态当成机器人真实状态。

## 54.5 操作步骤

1. 为每台机器人分配固定逻辑 ID 和命名空间。
2. 检查节点、话题、TF frame 和参数是否带唯一前缀。
3. 逐台上线，只验证状态订阅，不先发编队命令。
4. 启动 Qt 后用 `ros2 topic info --verbose` 核对发布者和订阅者。
5. 使用低速单车选择测试，确认不会控制错误机器人。
6. 再运行编队，记录网络延迟、丢包和掉队处理。
7. 关闭界面或编队节点，确认各底盘停止或回到安全模式。

## 54.6 验收标准

- 节点、话题和 TF 无跨车冲突。
- Qt 显示来自机器人反馈，而非本地假定。
- 选择单车时其他机器人不响应。
- 网络中断和上层退出后底盘安全停止。

## 54.7 故障排查

| 现象 | 检查 |
|---|---|
| 多车互相串话题 | 命名空间、绝对话题名和 remap |
| TF 树混在一起 | frame 前缀和 robot_state_publisher |
| Qt 显示正常但车不动 | 发布话题、QoS、控制优先级和底盘订阅 |
| 掉线后继续走 | 命令超时和失联策略 |
