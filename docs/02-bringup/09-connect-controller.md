# 9. 连接主控：显示器、SSH 与远程桌面

## 本章目标

选择合适的主控连接方式，并建立一条可重复的登录路径。本章重点不是记住某个默认 IP，而是知道怎样确认网络模式、获取当前 IP、验证链路，再选择命令行或图形桌面。

完成后应保存一条登录记录：客户端设备、网络名称、主控 IP、用户名、连接方式和验证时间。网络切换会改变 IP，这条记录必须带日期，不能当成永久配置。

## 适用范围

| 连接方式 | 适用场景 | 限制 |
|---|---|---|
| 本地显示器与键鼠 | 首次配置、网络完全未知、恢复故障 | 需要显示接口和物理接触主控 |
| SSH | 运行命令、编译、看日志、维护服务 | 默认不提供完整桌面；图形转发可能卡顿 |
| VNC/远程桌面 | RViz、图像窗口、桌面配置 | 服务端和分辨率需配置，带宽占用更高 |
| 串口/随车 IP 显示 | 无屏环境下获取 IP 或应急诊断 | 依赖硬件或预装脚本，不是所有机型都有 |

资料覆盖树莓派、Jetson Orin、RDK X5 等平台。热点切换脚本和路径随镜像版本变化，执行前必须确认文件存在。

## 开始前检查

1. 主控已完成第 3 章上电基线，没有反复重启。
2. 准备一台与主控能接入同一网络的电脑。
3. 查找随货信息中的热点名、密码、用户名和 IP。资料常见示例为 `wheeltec` 用户和 `192.168.0.100`，但实机信息优先。
4. 不在远程会话中贸然修改当前网卡模式。热点切换为 Station 后，现有 SSH 很可能中断。
5. 如果准备使用 VNC，先确保 SSH 或本地显示至少有一种可用恢复路径。

## 工作原理

### 热点和 Station 是两种角色

- 热点（Soft AP）模式：主控创建无线网络，电脑直接连接。优点是不依赖现场路由器，缺点是主控通常不能同时通过同一网卡访问外网。
- Station 模式：主控加入现有 Wi-Fi。电脑也加入同一网络后，通过路由器分配的 IP 访问主控。

切换模式后，主控 IP 可能改变。连接失败时先确认电脑和主控是否仍在同一网段，再检查 SSH 或 VNC 服务。

### SSH 和 VNC 解决不同问题

SSH 传输命令行，适合构建、启动节点和查看日志。`ssh -Y` 可以转发部分 X11 图形窗口，但相机画面或复杂界面可能卡顿。VNC 传输完整桌面，适合 RViz、OpenCV 窗口和桌面设置，但它依赖图形会话、共享设置和足够的网络带宽。

## 操作步骤

### 1. 选择最稳妥的第一次入口

按以下顺序选择：

1. 能接显示器时，先从本地桌面确认主控和 IP。
2. 主控发出已知热点时，电脑连接热点后使用 SSH。
3. 主控接入有线网时，从路由器租约或本地终端查 IP。
4. 无屏、热点未知时，使用随车 OLED、蓝牙/串口 IP 功能或供应商预装脚本。

不要先安装新的远程工具。先用系统自带的 SSH 建立最低依赖的维护入口。

### 2. 确认电脑端网络

在电脑上确认当前连接的 Wi-Fi 或有线网络，再检查本机 IP。

Windows PowerShell：

```powershell
ipconfig
```

Ubuntu 终端：

```bash
ip address
```

如果随货资料给出的主控 IP 是 `192.168.0.100`，电脑的对应网卡通常也应在 `192.168.0.0/24` 网段，但最终应以实际网络掩码和路由为准。

### 3. 测试主控是否可达

在电脑终端执行：

```bash
ping <主控IP>
```

Windows 可以使用：

```powershell
ping <主控IP>
```

ping 不通并不必然表示主控关机，防火墙也可能屏蔽 ICMP；但首次接入时，最常见原因仍是连错热点、IP 已改变或电脑虚拟机没有接入正确网卡。

### 4. 通过 SSH 登录

在电脑终端执行，替换实际用户名和 IP：

```bash
ssh <用户名>@<主控IP>
```

需要尝试 X11 图形转发时：

```bash
ssh -Y <用户名>@<主控IP>
```

首次连接会显示主机指纹。确认 IP 对应自己的机器人后再接受。登录成功后，在主控终端执行：

```bash
hostname
whoami
ip address
pwd
```

把输出写入连接记录。后续命令必须区分“电脑端终端”和“机器人主控终端”。

### 5. 虚拟机用户检查网络桥接

如果供应商 Ubuntu 环境运行在 VMware 中，电脑能连接机器人热点但虚拟机 ping 不通，优先检查虚拟机网卡模式。桥接模式通常让虚拟机直接进入机器人所在网络；NAT 模式是否可用取决于宿主机路由。切换后重新查看虚拟机 IP，不要沿用旧地址。

### 6. 需要图形桌面时使用 VNC

VNC 适合图形工具和视频窗口。先从 SSH 确认 VNC 服务存在并运行，再从客户端连接。不同镜像可能使用 GNOME Remote Desktop、Vino、TigerVNC 或其他服务，不能混用配置命令。

无显示器时，远程桌面分辨率可能较低。资料给出过如下示例命令：

```bash
xrandr --fb 1024x768
```

它只对当前图形会话和支持的显示环境有效。Orin 在插拔网线或修改 IP 后，桌面共享开关可能关闭，需要在本地设置或可用的桌面会话中重新启用。

### 7. 切换热点与 Wi-Fi 前建立回退方案

在主控从热点切换到 Station 前，记录：

- 当前热点的恢复脚本或设置入口；
- 新 Wi-Fi 的 SSID；
- 路由器中查找新 IP 的方法；
- 本地显示器或串口是否可用；
- 当前脚本是否匹配主控和镜像日期。

Jetson Orin、RDK X5 和树莓派的网络管理脚本与目录不同。切换热点或 Wi-Fi 前，先用 `ip addr`、`ip route` 和 `nmcli connection show` 确认当前状态，再按实际平台和 Ubuntu 版本修改；不要跨平台照搬脚本。

## 结果验收

完成本章后，应满足：

- 能明确说出主控当前处于热点、Station 还是有线网络模式；
- 能从至少一种可信来源获得当前 IP；
- SSH 登录可连续成功两次；
- 登录后 `hostname` 和 `whoami` 与记录一致；
- 若使用 VNC，图形会话可打开终端，断开后 SSH 仍是可用维护入口；
- 网络切换前已经记录恢复热点或本地登录的方法。

资料核对通过不等于所有机型都已实机验证。热点名、密码、IP 和脚本路径必须在自己的机器人上重新确认。

## 常见故障与处理

| 现象 | 检查顺序 |
|---|---|
| 电脑看不到机器人热点 | 等待主控启动 → 检查无线网卡 → 查有线网/显示器 → 核对是否已切到 Station |
| 电脑能连热点但 ping 不通 | 确认主控 IP → 检查电脑网卡 IP → 关闭错误代理/VPN 路由 → 检查虚拟机桥接 |
| ping 通但 SSH 拒绝连接 | 检查用户名、SSH 服务和端口；从本地终端确认 `sshd` 状态 |
| SSH 提示主机指纹变化 | 先排除 IP 被另一台设备占用或系统重装；确认后再更新 `known_hosts` |
| SSH 图形窗口很卡 | 改用 VNC；不要把 X11 转发性能问题误判为相机节点故障 |
| 切换 Wi-Fi 后 SSH 断开 | 这是 IP 或链路改变的常见结果；到路由器、串口或本地显示查新 IP |
| VNC 黑屏或分辨率异常 | 检查图形会话、共享开关、显示器模拟和 `xrandr` 支持情况 |
