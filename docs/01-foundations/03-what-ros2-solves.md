# 3. ROS 2 解决什么问题

## 本章要回答的问题

机器人主控上为什么要同时运行许多程序？ROS 2 在这些程序之间承担什么工作？

前两章已经介绍了机器人的部件以及程序、进程等电脑概念。本章在此基础上解释 ROS 2，不要求运行命令。

## 从一个具体场景开始

设想我们把摄像头采集、障碍判断、路径计算和电机控制全部写进一个大程序。开始时看起来很省事，但很快会遇到麻烦：

- 摄像头可能每秒产生几十帧图像，路径计算却不需要同样的更新频率；
- 更换摄像头后，整个程序都可能需要重新修改和测试；
- 视觉部分崩溃时，底盘控制也可能被一起拖垮；
- 想单独观察某一步的数据，会很困难。

更实际的做法是把工作拆开。一个程序负责读取摄像头，一个程序负责识别障碍，一个程序负责计算运动目标，另一个程序负责把目标交给底盘。问题随之变成：这些程序怎样找到彼此，怎样说明数据含义，又怎样观察谁正在工作？

## 新概念

### ROS 2

ROS 2 是一套用于开发机器人软件的框架和约定。它运行在 Ubuntu 等操作系统之上，为机器人程序提供通信方式、统一的数据定义、启动组织和观察工具。

ROS 2 不是电路板，不直接为电机供电；它也不是替代 Ubuntu 的另一套操作系统。名字中的“OS”来自项目沿用的名称，初学时把它理解为“让机器人程序协作的一套软件方法”更准确。

### 节点

在 ROS 2 中，负责一项明确工作的程序单元叫节点。节点的英文是 Node。

一台机器人上可能有：

- 读取激光雷达的节点；
- 发布摄像头图像的节点；
- 估计机器人位置的节点；
- 计算行驶路线的节点；
- 接收速度目标的底盘节点。

一个进程可以承载一个或多个节点。初学阶段先关注“每个节点负责什么、接收什么、产生什么”，不用急着研究它在进程中的具体组织方式。

### 节点之间的数据

节点之间不应该依赖对方的内部代码。雷达节点只需说明自己提供的是扫描数据，导航节点只需按照约定接收这种数据。这样更换雷达驱动时，导航逻辑不必全部重写。

ROS 2 为传递的数据规定类型。类型会说明数据有哪些字段，例如速度包含直线方向和转动方向，扫描数据包含测量角度与距离。双方使用相同的数据定义，才能正确理解内容。

## 图示或逐步例子

以“机器人看到障碍物后减速”为例，可以把软件拆成下面几步：

```text
雷达节点
  │ 产生距离数据
  ▼
避障节点
  │ 产生速度目标
  ▼
底盘节点
  │ 把目标交给底层控制
  ▼
控制板和电机
```

这里有三个软件节点和一组底层硬件。ROS 2 负责前三个节点之间的数据交换和观察；控制板继续负责电机附近的底层控制。

拆分后，我们可以单独回答这些问题：

1. 雷达节点是否产生了数据？
2. 避障节点是否收到了数据？
3. 避障节点算出的速度是多少？
4. 底盘节点是否收到了速度目标？

这种分层观察是后续排障的基础。

## 可选实验

选择一个熟悉的机器人任务，例如巡线、遥控或导航。在纸上写出完成任务需要的三到五项工作，然后尝试把每项工作分配给一个节点。

每个节点只写三行：

```text
节点名称：
接收什么：
产生什么：
```

这项练习不要求名称符合现成系统。重点是把任务拆成职责清楚的程序单元。

## 本章小结

复杂机器人通常由多个程序协作完成任务。ROS 2 提供程序发现、数据交换和运行观察的方法。在 ROS 2 中，承担一项明确工作的程序单元叫节点；节点通过约定好的数据类型交换信息。
