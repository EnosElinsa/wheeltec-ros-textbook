# 45. 固件架构与 FreeRTOS 任务

主控把速度命令交给底盘之后，控制板还要接收报文、读取编码器和 IMU、更新电机输出，并持续发送状态。这些工作既有周期要求，也会被串口接收等外设事件触发。阅读固件时，需要先看清它们怎样被安排执行。

固件是存放在控制板中、上电后直接运行的程序。WHEELTEC 底盘常用的 STM32 是一系列 MCU，集成了处理器、存储器、串口和定时器等外设；FreeRTOS 是面向微控制器的实时操作系统（Real-Time Operating System, RTOS），按优先级和周期调度任务。本章从程序入口进入初始化、中断与任务调度，再对应到命令接收、电机控制、传感器和状态发送，为后续逐模块阅读源码建立框架。

## 45.1 学习目标

画出固件初始化、中断与任务的调用关系，找到速度接收、电机更新、状态发送，以及自检失败后阻止电机使能的位置。

## 45.2 适用范围

WHEELTEC STM32 底盘固件。不同控制板的外设和任务名会变化，本文讲职责，不假定函数名完全一致。

## 45.3 操作前检查

- 只读当前匹配控制板的源码，不先改代码。
- 保存工程、编译器版本和宏定义。
- 能从源码恢复到出厂固件。

## 45.4 工作原理

### 初始化与任务调度 {#initialization-task-scheduling}

典型固件由启动初始化、周期任务和中断组成。中断会在外设事件发生时暂时打断当前任务，先处理接收数据或计时等紧急工作。串口/CAN 接收也可能使用DMA，让外设在较少占用处理器的情况下把数据写入内存。控制任务按周期更新运动学与 PI，传感器任务读取 IMU/编码器，通信任务发送状态，人机任务刷新 OLED、蜂鸣器和按键。

实时性取决于任务能否按约定周期及时运行。控制周期忽快忽慢会影响编码器测速、PI 参数和里程计积分；增加任务数量并不会改善实时性。

## 45.5 固件实验记录 {#firmware-evidence-record}

### STM32 串口、PWM 与编码器最小实验

三个实验分别观察串口收发、定时器 PWM 输出，以及编码器计数和方向。按源码阅读、工程构建、接线测量的顺序进行，具体步骤见第 46 章。

### 实验板与工具链

示例工程面向 `STM32F103C8T6` 核心板，使用 Keil MDK 5.33、Arm Compiler 5.06 update 7 和 STM32F1 标准外设库。移植到 C30D、C50 或 R680 时，应按实际控制板重新配置芯片、引脚、时钟、下载地址和电平，并准备原固件与恢复方法。

开始前必须记录：

| 项目 | 需要确认的内容 |
|---|---|
| 目标板 | 完整型号、MCU 丝印、供电电压和原理图版本 |
| 工程 | 目标芯片、启动文件、Flash/RAM 地址、库和编译器版本 |
| 下载 | ST-Link/串口下载方式、SWD/BOOT 接线和可用回滚文件 |
| 测量 | 万用表或示波器量程、探头衰减、逻辑地连接 |
| 安全 | 电机断开或失能、急停可用、没有未知外设占用测试引脚 |

!!! danger "先核对板卡，再接线或烧录"
    示例使用 `PA0`、`PA9`、`PA10`、`PB6` 和 `PB7`。接线前，按当前板卡原理图确认引脚用途、供电和电平；烧录前，确认 MCU、目标地址和恢复文件。信息不全时先保持断电，查清后再操作。

每项实验开始前还要写下数值验收门槛，例如允许的逻辑电平、频率误差、静止计数和重复测量偏差。门槛来自当前芯片/板卡规格、时钟误差和仪器精度；“接近”“明显”或“偶尔”不能单独作为通过标准。普通验收失败应停止本项并排查，过压、发热、复位、机械运动等安全停止条件则应立即断电。

### 统一实验记录

| 字段 | 记录内容 |
|---|---|
| 实验 | 串口 / PWM / 编码器 |
| 板卡与 MCU | 丝印、原理图版本、供电 |
| 工程基线 | 工程副本、目标芯片、编译器、库、提交或文件哈希 |
| 接线 | MCU 引脚、外设端、地和电平 |
| 配置 | 串口帧格式 / TIM 时钟、PSC、ARR、CCR / 编码器模式 |
| 预期值 | 手算结果或预期字节/方向 |
| 实测值 | 串口记录、波形截图、计数和时间窗 |
| 偏差 | 偏差大小、可能原因和复测结果 |
| 验收门槛 | 逻辑电平、频率误差、静止计数、重复测量误差 |
| 安全状态 | 执行器是否失能、急停、供电和停止条件 |
| 结论 | 通过 / 失败 / 待实机验证 |

## 45.6 验收标准

- 有一张命令到执行、反馈到上报的任务图。
- 控制周期和测速周期明确。
- 自检、急停、通信超时和电机失能路径可定位。
- 共享变量的生产者、消费者和更新时机明确。

## 45.7 故障排查

| 现象 | 检查 |
|---|---|
| 偶发速度跳变 | 接收帧一致性、共享变量和任务周期 |
| OLED 卡住但电机仍动 | 人机任务阻塞或优先级问题 |
| 通信正常但控制更新慢 | 控制任务延时、阻塞调用或优先级 |
| 自检偶发失败 | 初始化顺序、传感器稳定时间和电压 |
