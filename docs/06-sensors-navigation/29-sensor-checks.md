# 29. 传感器自检

## 29.1 学习目标

分别检查设备、节点和话题。只有这三层都通过，底盘、IMU、雷达或相机才算具备建图、导航所需的数据条件。

## 29.2 适用范围

ROS 2 机器人常见 USB/串口雷达、相机、板载或外置 IMU。设备名和话题名以实机为准。

## 29.3 操作前检查

- 主控环境和底盘基础节点已确认。
- 逐个接入传感器，保存原 USB 端口位置。
- 不同时启动建图、导航和视觉应用。

## 29.4 工作原理

### 三层证据

传感器把物理世界的信息变成可读取的数据。激光雷达（Light Detection and Ranging, LiDAR）用激光测量周围物体的距离；惯性测量单元（Inertial Measurement Unit, IMU）测量加速度和角速度；相机输出图像。设备层说明 Linux 能看到硬件；节点层说明驱动已运行；话题层说明数据类型、频率和内容可用。`lsusb` 有设备但话题无数据，问题通常仍在驱动、权限或参数，不在 Navigation2（Nav2）。

### 排障顺序

传感器排障先按既有检查链进行：设备 → 节点 → 话题 → 通信匹配 → 时间；在这条链中，驱动检查位于设备识别与节点运行之间。为适应建图、定位和视觉应用，本书把最后两步展开为时间/坐标 → 算法。前一层没有证据时，先不要进入后一层。设备存在不代表驱动节点能打开它；节点存在不代表正在发布；话题存在也不代表发布端与订阅端的策略兼容。消息最终还要带有效时间戳和正确的 `frame_id`，建图、定位等算法才能把它与其他传感器和坐标数据对齐。

## 29.5 操作步骤

### 设备层

设备层：

```bash
lsusb
ls -l /dev/ttyUSB* /dev/ttyACM* /dev/video* 2>/dev/null
dmesg --ctime | tail -n 100
```

### 节点与话题层


```bash
ros2 node list
ros2 topic list -t
ros2 topic info <话题名> --verbose
ros2 topic hz <话题名>
ros2 topic echo --once <话题名>
```

`topic info --verbose` 中比较发布端和订阅端的通信策略。再查看一条消息的 `header.stamp` 与 `frame_id`；频率正常但时间或坐标标识错误的数据，仍不能直接交给建图和导航。

### 数据合理性

底盘/IMU：静止时速度接近零，轻推或转动后符号合理。雷达：扫描频率稳定，距离不是全零/无穷，遮挡方向与实物一致。相机：图像话题频率稳定，编码和尺寸符合配置。

没有实机或需要复现历史数据问题时，按 [ROS 1 Bag 离线传感器诊断](../appendices/a-ros1-maintenance.md#ros1-bag-offline-diagnostics)在隔离 master 中检查频率、时间戳、frame 和消息内容。Bag 回放只能替代数据输入，不能替代设备层和驱动层验收。

## 29.7 故障排查

设备反复断开时先完成设备层检查；设备稳定后检查驱动节点和话题，再检查通信匹配、时间与坐标。建图、定位或视觉应用仍无输出时，最后读取算法节点的参数和日志。

| 现象 | 处理 |
|---|---|
| 设备反复断开 | 查供电、USB 线、集线器和 dmesg |
| 串口权限不足 | 查 udev 规则和用户组，不长期用 root 绕过 |
| 节点在但频率为 0 | 查设备参数、端口占用和驱动日志 |
| 数据频率忽高忽低 | 查 CPU、USB 带宽、供电和 QoS |
