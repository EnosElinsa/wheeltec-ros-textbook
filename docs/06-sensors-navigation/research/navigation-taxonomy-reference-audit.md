# 第 33 章地图依赖分类核查说明

本记录对应 2026 年 11 月 12 日按三条导航路线重写的[第 33 章](../33-relocalization-map-dependence.md)。[分类证据表](navigation-taxonomy-evidence.csv)保留原文位置、短引文和文件哈希。此前的[重定位核查](relocalization-reference-audit.md)与[在线导航核查](online-navigation-reference-audit.md)保留各自日期和范围。

## 分类依据与本章判据

DeSouza 与 Kak 的经典综述在室内视觉导航部分区分基于地图、基于建图和无地图三类。第 33 章借鉴这一框架，按已有地图依赖、在线空间建模和直接感知控制组织讲解。第 33 章结合现代激光、视觉和学习系统的输入与空间信息组织方式，解释这三类方法。

为避免类别重叠，本章分别检查各个运行阶段：先判断是否依赖工作区域已有的地图、场景记录或定位模型，再判断是否在线建立供定位或规划使用的环境模型。人工带领记录路线、机器人自主重复行驶两个阶段分别判断，论文模块与完整系统分别核对。地图表示、覆盖范围、全局一致性、位置来源和加载方式则另外比较。

## 导航分类与重定位方案的关系

后续修订将导航三分法保留在正文第 33.1 节，作为理解环境信息从何而来的背景。三分法描述导航系统的信息组织方式，不是三类重定位算法，也不能据分类名称推断系统具备重定位能力。

正文随后围绕原问题比较全局地图匹配、代表性历史观测、沿线局部地图、建筑资料或场景模型，以及外部定位。所比较的做法可以组合使用，不作为另一套互斥分类。在线建图与无显式地图方法用于说明它们减少了哪些地图准备工作，以及恢复原地图位姿时还需要哪些条件。FRTree 等方法的完整规划流程移至[补充说明](relocalization-method-notes.md#online-navigation-methods)，已核查的来源、证据表和结论边界保持不变。

## 代表工作与结论的处理

FRTree 的自由区域树与 Active NTFields 的在线场景模型归入在线建模。当前扫描控制屏障函数在控制模块层面归入无显式地图，同时保留 Vicon 位置来源的实验条件。MTG、DTG 区分训练监督与运行输入，DTG 的完整系统还组合局部规划器，分类时需同时核对轨迹模块与完整系统的运行输入。

FusedNet 通过训练，将场景与坐标的联系保存在参数中，归入依赖已有环境信息的方法。沿已记录路线自主行驶也使用已有环境数据，但只需利用局部地图及地点连接，无须先将所有局部地图精确拼接成一张大地图。正文据此说明，导航可以不预建完整地图，而依靠环境匹配恢复定位时，仍需保存预期恢复区域的数据。

用户提供的无人机稿件先将扫描整理成局部高程栅格，再滚动优化路径，其机制属于在线局部建模。该稿件的公开出版身份尚未验证，本轮没有新增正式引文或采用其性能数字。FRTree 与 Active NTFields 已为相应机制提供可核查的正式来源。

本轮首先复用库内综述与已有方法证据。此前外部发现检索用于寻找分类原始出处，候选元数据用于筛选来源，具体论断结合原文核查。Bonin-Font 等人的相关综述因官方访问受限未取得全文，也未用于支持本章结论。这些来源用于解释本次章节采用的分类与方法。
