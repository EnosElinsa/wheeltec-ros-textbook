# 49. 日志、备份、升级与恢复

## 49.1 学习目标

在升级前留下可恢复基线，升级后能判断改变了什么。配置、源码、固件、地图和系统镜像应分别备份，并为每一类内容记录版本、校验值和恢复位置。

## 49.2 适用范围

所有 WHEELTEC 主控和底盘控制板。系统镜像工具按树莓派、Jetson、RDK、Atlas 和 IPC 平台选择。

## 49.3 操作前检查

- 第 48 章的部署基线和本章需要备份的对象已经列出；最终验收由下一章统一执行。
- 备份介质容量、校验方式和存放位置明确。
- 升级窗口内有人能执行急停、断电和本地恢复。

## 49.4 工作原理 {#backup-layers}

### 备份层次与恢复点

系统镜像（System Image）是操作系统、驱动和预装软件的整盘或分区副本，适合恢复无法正常启动的主控。文件级备份则保存配置、ROS/STM32 源码与固件、地图和日志，恢复范围更小。恢复系统镜像可能覆盖之后写入的文件，因此应先确认系统可启动，再依次恢复环境、源码/固件、配置和地图，最后重新验收功能。

哈希值（Hash Value）是根据文件内容计算出的固定长度结果。备份前后哈希一致，可以证明复制过程中内容没有改变；它不能代替版本说明，也不能证明文件与当前硬件兼容。

## 49.5 操作步骤

### 备份与升级

### 升级前

保存：

```text
baseline/
├── hardware.md
├── os-and-ros.txt
├── workspace-file-list.txt
├── configuration/
├── firmware/
├── maps/
├── logs/
└── checksums.sha256
```

记录 `ros2 pkg prefix`、关键参数、设备列表、TF、话题频率和启动日志。固件还要记录控制板、车型、编码器、TYPE、纠偏值和舵机零位。

### 升级后

1. 先确认系统能启动、网络可用。
2. 再确认 ROS 环境和工作空间。
3. 只启动底盘，完成低速停止测试。
4. 逐个恢复传感器、TF、地图和导航。
5. 对比升级前后日志和参数，不要一次启动所有应用。

### 恢复

先恢复最近一次可启动系统，再恢复源码/固件和配置，最后恢复地图与应用。每层恢复后都执行对应验收，不跨层猜测。

## 49.6 验收标准

- 备份文件可读，哈希记录完整。
- 至少演练一次从备份恢复配置或固件。
- 升级前后平台、ROS、源码和参数差异有记录。
- 失败时能回到已验证的底盘停止状态。

## 49.7 故障排查

| 现象 | 处理 |
|---|---|
| 备份存在但无法恢复 | 校验文件、版本、工具和介质 |
| 升级后 ROS 启动但底盘不动 | 分层检查串口、固件、参数和使能 |
| 地图加载失败 | 路径、权限、分辨率和版本 |
| 自启动进入重启循环 | 禁用服务，回到手动基线 |

    本章处理读者系统中的日志、备份和恢复介质，不依赖源码仓库中的专用代码资源。
