# 23. 修改、编译并回滚机器人源码

## 本章目标

建立固定循环：保存基线、做单一修改、局部构建、加载新环境、运行验收、失败回滚。任何源码改动都应留下可复现记录。

## 适用范围

ROS 2 参数、Launch、Python 和 C/C++ 功能包。固件修改见卷五。

## 开始前检查

- 当前版本能运行，基线日志已保存。
- 复制待改文件，记录来源工作空间。
- 知道停止节点和恢复旧文件的方法。

## 工作原理

最危险的不是编译失败，而是同时改多处后“似乎能跑”。一次只改变一个假设，局部构建并验证原始症状，才能确定因果关系。

## 操作步骤

建立修改记录：

```text
目标：
原始现象：
文件与原值：
预期变化：
验收命令：
回滚文件：
```

修改后构建：

```bash
cd <工作空间>
colcon build --symlink-install --packages-up-to <目标包>
```

在新终端加载并确认路径：

```bash
source /opt/ros/$ROS_DISTRO/setup.bash
source <工作空间>/install/setup.bash
ros2 pkg prefix <目标包>
```

运行最小功能，保存节点、话题和日志。失败时停止进程，恢复文件，再局部构建并重复同一验收。不要在失败现场继续叠加第二个“顺手修复”。

## 结果验收

- 修改目标和预期结果写清楚。
- 构建只覆盖必要包。
- 运行环境确实加载新工作空间。
- 原始症状按预期变化，相关基础功能没有退化。
- 回滚后行为恢复到基线。

## 常见故障与处理

| 现象 | 处理 |
|---|---|
| 改动没有效果 | 查实际加载路径、安装副本和进程是否重启 |
| 回滚仍异常 | 检查构建产物、参数持久化和其他同时修改 |
| 编译通过但运行崩溃 | 查接口、参数类型、共享库和运行日志 |
| 依赖安装破坏环境 | 使用包管理记录或系统镜像恢复，不盲目降级全局库 |
