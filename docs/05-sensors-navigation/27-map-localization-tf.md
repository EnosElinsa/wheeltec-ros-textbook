# 27. 地图保存、定位与坐标验证

## 27.1 学习目标

加载已保存地图，建立 `map → odom → base_link` 链，设置初始位姿，并用可观察数据判断定位是否可信。

## 27.2 适用范围

二维占据栅格地图与 ROS 2 定位系统。具体定位节点随镜像而异。

## 27.3 操作前检查

- 地图文件和元数据成对存在。
- 底盘里程计、IMU、雷达与 TF 已通过。
- 机器人在地图中有可辨认的初始区域。

## 27.4 工作原理

第 26 章的 SLAM 地图记录了场地的固定轮廓；定位系统把机器人当前的雷达扫描与这张地图比较，估计机器人在地图中的位置。Transform Library 2（TF2）用一棵坐标树把这项估计交给底盘、传感器和导航节点。移动机器人常用的完整链路是 `map → odom → base_link → sensor`。`map` 是全局稳定坐标，`odom` 保持局部连续但会漂移，`base_link` 随机器人运动，最后一级表示雷达、相机等传感器相对机身的安装位置。

定位系统估计 `map → odom`，底盘里程计提供 `odom → base_link`，静态发布器或机器人模型提供 `base_link → sensor`。三段关系由不同来源负责；同一段出现多个发布者时会造成坐标跳变和冲突。

## 27.5 操作步骤

1. 加载地图，确认 YAML 中图像路径、分辨率和原点正确。
2. 启动定位节点，检查是否只有一个 `map → odom` 发布者。
3. 在 RViz 中给出初始位姿，方向箭头与车头一致。
4. 缓慢移动并回到原处，观察雷达扫描与墙线是否持续贴合。
5. 记录 `/tf`、`/tf_static`、里程计和定位粒子/位姿话题。
6. 若使用 EKF，确认它融合的传感器和输出坐标，不重复融合同一信息。

使用录制数据复现 TF 问题时，参考 [ROS 1 Bag 离线传感器诊断](../appendices/a-ros1-maintenance.md#ros1-bag-offline-diagnostics)，分别检查 Bag 中的 `/tf`、里程计 `header.frame_id`、`child_frame_id` 和传感器 frame。`/tf` 存在不代表整条链连续。

## 27.6 验收标准

- TF 链完整且无多个发布者争用。
- 初始位姿后扫描与地图对齐。
- 短距离往返后定位误差可接受，没有突然跳变。
- 停止时位姿不过度漂移。
- 重启后能重新加载地图并完成定位。

## 27.7 故障排查

先回到第 25 章确认雷达、IMU 和底盘设备数据，再确认定位与里程计节点及其话题。随后检查 TF、时间戳和地图坐标；基础链路通过后，再评估扫描匹配和融合配置。

| 现象 | 检查 |
|---|---|
| 地图存在但机器人不显示 | Fixed Frame、TF 链和时间 |
| 初始位姿后仍错位 | 方向、地图原点、雷达 TF 和环境变化 |
| 位姿不断跳 | 多个定位/TF 发布者、里程计异常或扫描匹配失败 |
| 行驶越远偏差越大 | 轮径轮距、打滑、IMU 零偏和融合配置 |
