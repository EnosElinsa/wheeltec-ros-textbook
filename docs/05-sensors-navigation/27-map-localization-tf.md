# 27. 地图保存、定位与坐标验证

## 本章目标

加载已保存地图，建立 `map → odom → base_link` 链，设置初始位姿，并用可观察数据判断定位是否可信。

## 适用范围

二维占据栅格地图与 ROS 2 定位系统。具体定位节点随镜像而异。

## 开始前检查

- 地图文件和元数据成对存在。
- 底盘里程计、IMU、雷达与 TF 已通过。
- 机器人在地图中有可辨认的初始区域。

## 工作原理

`map` 是全局稳定坐标，`odom` 保持局部连续但会漂移，`base_link` 随机器人运动。定位系统估计 `map → odom`，底盘里程计提供 `odom → base_link`。两条职责混在一个节点里，容易造成 TF 冲突。

## 操作步骤

1. 加载地图，确认 YAML 中图像路径、分辨率和原点正确。
2. 启动定位节点，检查是否只有一个 `map → odom` 发布者。
3. 在 RViz 中给出初始位姿，方向箭头与车头一致。
4. 缓慢移动并回到原处，观察雷达扫描与墙线是否持续贴合。
5. 记录 `/tf`、`/tf_static`、里程计和定位粒子/位姿话题。
6. 若使用 EKF，确认它融合的传感器和输出坐标，不重复融合同一信息。

## 结果验收

- TF 链完整且无多个发布者争用。
- 初始位姿后扫描与地图对齐。
- 短距离往返后定位误差可接受，没有突然跳变。
- 停止时位姿不过度漂移。
- 重启后能重新加载地图并完成定位。

## 常见故障与处理

| 现象 | 检查 |
|---|---|
| 地图存在但机器人不显示 | Fixed Frame、TF 链和时间 |
| 初始位姿后仍错位 | 方向、地图原点、雷达 TF 和环境变化 |
| 位姿不断跳 | 多个定位/TF 发布者、里程计异常或扫描匹配失败 |
| 行驶越远偏差越大 | 轮径轮距、打滑、IMU 零偏和融合配置 |
